# Scenario 14 — The v0.1 criterion of plugin-orchestrator, with plugin-flutter 1.0

**Goal**: the first success criterion of plugin-orchestrator's PRD, measured with both plugins —
a single-part Flutter project carried from end to end: bootstrap (scenario 1), one feature in TDD
with RED then GREEN recorded (commands and exit codes), a clean commit, and recovery after an
interruption. Every language gesture goes through a mandate to a plugin-flutter agent, whose
report carries `INTERFACE: 1`; no workflow of plugin-flutter runs, and no hook runs twice. Needs
`FORGE_ORCHESTRATOR_DIR` and the project of scenario 1, with its rules copied and the PRD and the
TRD approved by the user (`orch.sh approve`).

## Steps

```bash
P="$WORK/demo_notes"
bash "$FORGE_ORCHESTRATOR_DIR/scripts/orch.sh" approve "$P/docs/product/PRD.md" --quote "je valide"
bash "$FORGE_ORCHESTRATOR_DIR/scripts/orch.sh" approve "$P/docs/technical/TRD.md" --quote "je valide"
SID=$(uuidgen)
"$H" "$P" "$SID" new "$WORK/s14-1.jsonl" "/plugin-orchestrator:create-feature AC-001" "${TOOLS[@]}"
```

Expected: PRD and TRD read and APPROVED by `orch.sh status`, plan, branch `feature/AC-001-…`, one
Agent call with `plugin-flutter:test-engineer` on a `write-tests` mandate at interface 1, its RED
rerun by the session with `toolchain.test`, then the implementation, GREEN, `toolchain.format`,
`toolchain.analyze`, one Agent call with `plugin-flutter:code-reviewer` on a `review` mandate with
`--cached main`, the docs, and the commit proposed. Interrupt the session after the RED is
recorded in `.forge/checkpoint.md` (Ctrl-C, or end the turn there), then:

```bash
"$H" "$P" "$(uuidgen)" new "$WORK/s14-2.jsonl" "/plugin-orchestrator:recover-session" "${TOOLS[@]}"
```

Expected: the checkpoint read and compared with Git, only the recorded command rerun, nothing
changed before the user agrees; the work then resumes and ends on the commit.

## Checks

```bash
jq -r 'select(.type == "assistant") | .message.content[]? | select(.type == "tool_use") | "\(.name) \(.input.subagent_type // .input.skill // .input.command // "")"' "$WORK"/s14-*.jsonl
jq -r 'select(.type == "user") | .message.content[]? | select(.type == "tool_result") | .content | tostring' "$WORK"/s14-*.jsonl | grep -c '^INTERFACE: 1'   # one per report
grep -E 'RED|GREEN|exit' "$P/.forge/checkpoint.md"
git -C "$P" log --oneline
jq -c 'select(.type == "system" and .subtype == "hook_response") | .hook_name' "$WORK/s14-1.jsonl" | sort | uniq -c   # no guard twice
```

**Passed** when RED and GREEN are recorded with their commands and exit codes, every report of a
plugin-flutter agent carried `INTERFACE: 1`, the commit is clean, the recovery changed nothing
before agreement, and no guard hook appears twice for one tool call.
